Your Team Responsibilities Private capital index calculation is an unusually strict engineering problem. The inputs are irregular, sparse and revised, the measures are non-linear and solver-based, and the output is a published number that a client can hold us to for a decade. A run has to reproduce bit-for-bit against the exact code that was validated. This is not writing pipelines around someone else's library. It is building the library itself: the plugin contract, the solver, the aggregation, and the harness that proves the whole thing still does what it did last quarter. Your Key Responsibilities The measure catalogue: money-weighted (IRR, pooled, neutrally weighted), multiples, time-weighted (Modified Dietz, unitised, index-level chaining), public-market equivalents (Direct Alpha, KS-PME, Long-Nickels), and real-asset measures, each behind one stable, versioned, conformance-tested contract. Numerical correctness as a system property: exact decimal arithmetic end to end, with no IEEE floats anywhere near money or an IRR solve; a safeguarded solver that brackets before it iterates; and a canonical flow order, since fixed-precision summation is not associative. Reproducibility: every run pinned to a snapshot, an engine version, a measure version and an input hash, replayable to identical output, with a mechanism that makes a replay mismatch obvious rather than silent. The conformance harness: golden vectors from the methodology documents run on every build, and invariants such as date-shift invariance, netting invariance, weight sums and monotonicity are expressed as tests rather than intentions. Performance where it is load-bearing: a whole-estate batch handled as one pass over roughly 15,000 funds shared across roughly 150 definitions, not 150 separate passes, with memorization keyed on the snapshot so that re-ingesting an extract invalidates rather than serves a stale series. Your skills and experience that will help you excel Software engineering: strong engineering against a typed contract, with a linter that enforces the numerical rules and tests that function as the specification. Language is negotiable; rigour is not. Fixed-precision and floating-point: genuine comfort with both, including a clear instinct for where the two must never mix. Root-finding and numerical stability: bracketing, convergence, ill-conditioning, and knowing when a converged answer is still meaningless. Verification habit: a habit of testing a claim rather than asserting it. In this domain, plausible, confident, wrong numbers are the default failure mode.
