Your Team Responsibilities Private capital index calculation is a demanding engineering problem. Inputs are irregular, sparse and often revised. The measures are non-linear and solver-based, and the published output is a number that clients rely on for a decade. Every run must reproduce bit-for-bit against the validated code. You will build the calculation library itself, including the plugin contract, the solver, the aggregation logic and the test harness that confirms results have not changed. Your Key Responsibilities Design and build the measure library: money-weighted (IRR, pooled, neutrally weighted), multiples, time-weighted (Modified Dietz, unitised, index-level chaining), public-market equivalents (Direct Alpha, KS-PME, Long-Nickels) and real-asset measures, each exposed through a stable, versioned, conformance-tested interface. Implement numerically sound logic: exact decimal arithmetic throughout, no floating-point types for money or IRR solves, a safeguarded solver that brackets before iterating, and a canonical flow order for summation. Make every calculation reproducible: pin each run to a data snapshot, engine version, measure version and input hash, so replays produce identical output and any mismatch is flagged. Build and maintain the conformance harness: golden vectors from the methodology documents run on every build, with invariant tests for date-shift, netting, weight sums and monotonicity. Optimise batch performance across roughly 15,000 funds and roughly 150 definitions in a single pass rather than 150 separate passes, with caching keyed on the data snapshot so re-ingested extracts invalidate stale results. Work with methodology, data and product teams to turn methodology documents into tested code, and review changes to numerical code. Your skills and experience that will help you excel Strong software engineering experience in a typed language, with linting and tests that enforce numerical rules and act as the specification. Working knowledge of fixed-precision and floating-point arithmetic, and a clear sense of where the two must never mix. Root-finding and numerical methods, including bracketing, convergence, ill-conditioning, and recognising when a converged result is still meaningless. A disciplined testing habit: test claims rather than asserting them, since plausible but wrong numbers are the main failure risk in this domain. Preferred Qualifications: Experience with performance measurement or financial calculation libraries, ideally for private markets. Experience building versioned, reproducible computation pipelines.
