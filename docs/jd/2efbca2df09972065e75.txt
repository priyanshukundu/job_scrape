About the team The Batch Compute Experience team owns the platform that Stripe engineers use to build, run, debug and optimize Apache Spark jobs. Those jobs handle large-scale data processing for analytics, machine learning, finance and core product data pipelines. Hundreds of engineers and thousands of production jobs driving critical business processes, such as payouts and reconciliations, run on this platform. Today, diagnosing and tuning a job means reasoning by hand across scattered telemetry, configuration, query plans and application code. Our goal is to make Spark at Stripe fast to iterate, reliable by default, and self-optimizing, so engineers can focus on business logic instead of Spark internals. We're doing this through three connected efforts: Modernization : keeping Stripe's Spark runtime and dependency stack current, including Spark 3.5 → Spark 4, Scala 2.13 and Apache Iceberg. We're building automated upgrade and validation tools so that upgrading the whole fleet becomes routine and low-risk instead of a multi-year manual effort Agentic Spark and optimization : building trustworthy, AI-powered workflows that diagnose failed or underperforming jobs, recommend fixes based on evidence, and carry them safely into configuration changes, code PRs or escalations. We also want to optimize configuration, query plans and code across the whole fleet Operational excellence : making the platform reliable, observable and compliant, and defining user-experience metrics that show whether we're succeeding Over the longer term, we want to turn the platform into a Spark control plane that keeps learning. It should detect problems before users notice them, validate fixes safely and apply them through policy-controlled automation. Identify, prove out and roll out the highest-value configuration and query-plan optimizations, such as shuffle and adaptive query execution (AQE) tuning, executor sizing, join strategy and partitioning.
