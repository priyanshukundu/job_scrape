Make your impact at a leading Fintech Company BILL's accounts payable, accounts receivable and accountant products are how hundreds of thousands of small and midsize businesses pay and get paid. We are rebuilding the web experience for these products, and we are doing it with AI coding agents as a core part of how engineers work. As a Staff Frontend Engineer, you will rebuild high-traffic product workflows. You will move them onto a modern, component-driven architecture built on our design system, and you will set the patterns other engineers and their agents follow. This is a hands-on product engineering role: you ship customer-facing UI every day. In this role you will: Rebuild core AP and AR web flows (bills, invoices, payments, approvals, vendor and customer management) in TypeScript with Angular and React, replacing legacy screens without disrupting customers. Own frontend architecture for your area. Decide what belongs in the host application and what earns being a micro-frontend, and set the patterns for state, typed data access over our federated GraphQL API, performance, accessibility and testing. Work AI-first across the whole software lifecycle, from design through production, as described in the next section. Build with our design system, which serves both our Angular and React apps, and contribute components and patterns back so the two stay in step. Treat every query and mutation as a product surface, not a private helper for one screen. The operation that powers a page is the same one an AI agent or partner integration calls, so you design it with backend engineers before the UI is built and name and type it for consumers who have never seen the screen. Partner with backend engineers to move business rules out of the UI and into shared APIs, so web, mobile, developer APIs and AI tools all behave the same way. Plan and run incremental migrations: feature flags, staged rollouts, parity checks against the legacy experience. Raise the bar for the engineers around you through design reviews, code reviews and mentoring. How you will work: AI-first across the lifecycle AI-first here means rethinking how the work gets done across the whole software lifecycle, from design through production, not running the old process faster. We judge it by what ships and the difference it makes for customers. You stay accountable for quality, design and production outcomes, whoever or whatever wrote the code. You will: Inception and design: use agents to explore the legacy screens and code and map existing behavior and edge cases, then go straight to a working proof of concept in place of a research spike. Design discussion happens over running code, and design docs and decision records capture what was decided. Partnering across teams: use AI to learn other teams' APIs, components and conventions before asking for their time, and bring design, product and backend partners a working prototype or draft contract to react to. Build and test: break work into well-specified, verifiable tasks that agents can execute, with type checks, linters, visual regression and accessibility checks as guardrails. Code review: use agents for first-pass review against team standards, so human review time goes to design, risk and customer impact. Deployment: automate release readiness, feature-flag changes, staged rollouts and rollback checks. Production monitoring: use agents to watch dashboards, logs and alerts, triage issues, find root cause, and turn what you learn into tests and standards. Reusable skills and agents: codify architecture patterns, design system component usage, migration recipes and review checklists as skills, agents and templates that other engineers and their agents use by default. Keep team conventions in the repo where agents can read them, fold review feedback back into these skills so the same comment is never needed twice, and treat them as products with owners and versions. Shared AI infrastructure: build on BILL's shared AI platform and tooling instead of one-off solutions, and contribute skills, tool integrations and improvements back so every team benefits. We’d love to chat if you have: 8+ years of professional frontend engineering experience building complex, data-heavy web applications. Expert TypeScript, HTML and CSS, with deep experience in both Angular and React. A track record of leading a rebuild or large migration of a production web application from a legacy stack, end to end. Hands-on, daily use of AI coding agents (for example Claude Code or Cursor) to ship production code, with good judgment about when agent output can be trusted and how to verify it. Examples of using AI beyond code generation, in design, review, testing, release or production operations, with measurable impact on delivery or quality. Experience building reusable agent assets (skills, context files, custom agents, tool integrations) that other engineers adopted, ideally on a shared internal AI platform you contributed back to. A record of production impact at scale: software that serves a large user base or moves significant money and has run reliably over time. We care more about what you shipped and how it held up than about the list of tools you used. Experience building on and contributing to a design system or shared component library. Experience with large frontend monorepos and module federation, and the judgment to know when a micro-frontend is worth its cost. Strong GraphQL experience on the client: typed operations and code generation, caching, and co-designing schemas with backend teams. Federated GraphQL experience is a plus. A track record of moving business logic, permissions or workflow rules out of a frontend and into backend APIs. Strong testing practice across unit, integration and end-to-end layers. For Senior Staff (P5): experience setting frontend technical direction across several teams and landing it. Nice to have: experience in payments, invoicing, accounting or another correctness-critical, regulated domain and experience exposing APIs as tools for AI agents (for example through MCP).
