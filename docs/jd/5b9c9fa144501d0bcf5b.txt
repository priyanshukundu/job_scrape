Make your impact at a leading Fintech Company BILL's accounts payable, accounts receivable and accountant products move money for hundreds of thousands of small and midsize businesses. We are rebuilding the backend behind these products so that every capability is built once, in a clean API, and is available to web, mobile, developer APIs and AI agents on the same day. As a Staff Backend Engineer, you will rebuild core AP and AR services. You will design the domain models and API contracts, migrate behavior out of legacy code, and use AI coding agents as a core part of how you work. This is a hands-on product engineering role in a domain where correctness matters: the code you ship decides whether a payment is approved, scheduled and sent. In this role you will: Rebuild core AP and AR backend capabilities (bills, invoices, payments, approvals, vendors and customers) as well-bounded services with consistent, well-documented APIs. Build each capability once, headless. Move business rules out of the UI and legacy code paths into the service layer, and expose it through our federated GraphQL API for web, mobile and AI agents, and through REST for developers and partners. A capability is done when it is ready for all of them, not when it works in the web UI. Apply and help shape BILL's API standards: common types defined once across REST, GraphQL and events, consistent list APIs, business operations as explicit actions with server-owned status, idempotent writes for anything that moves money, and errors a developer or an AI agent can act on. Enforce them in code, not in review, with contract tests, schema checks and linters in CI. Work AI-first across the whole software lifecycle, from design through production, as described in the next section. Migrate live, high-volume financial workflows and their APIs without breaking customers or consumers: parity tests, staged rollouts, dual writes, backfills, reconciliation and rollback paths for data; additive changes, expand-and-contract and deprecation windows for contracts. Make APIs usable by AI agents as well as people: self-describing schemas with documentation an LLM can read, responses that return related data in one call instead of many, and AI tools that are a thin layer over the same queries and mutations that web, mobile and internal clients use. Own reliability for what you build: observability, on-call readiness, performance and data integrity. Raise the bar for the engineers around you through design reviews, code reviews and mentoring. How you will work: AI-first across the lifecycle AI-first here means rethinking how the work gets done across the whole software lifecycle, from design through production, not running the old process faster. We judge it by what ships and the difference it makes for customers. You stay accountable for quality, design and production outcomes, whoever or whatever wrote the code. You will: Inception and design: use agents to explore legacy code and data and map existing business rules and edge cases, then go straight to a working proof of concept in place of a research spike. Design discussion happens over running code, and design docs and decision records capture what was decided. Partnering across teams: use AI to learn other teams' services, contracts and conventions before asking for their time, and bring frontend, product and platform partners a draft API contract or working prototype to react to. Build and test: break work into well-specified, verifiable tasks that agents can execute, with contract tests, parity tests against legacy behavior and deterministic checks as guardrails. Code review: use agents for first-pass review against team standards, so human review time goes to design, risk and data integrity. Deployment: automate release readiness, migration steps, staged rollouts and rollback checks. Production monitoring: use agents to watch dashboards, logs and alerts, triage incidents, find root cause, and turn what you learn into tests and standards. Reusable skills and agents: codify architecture patterns, service scaffolds, API standards, migration recipes and review checklists as skills, agents and templates that other engineers and their agents use by default. Keep team conventions in the repo where agents can read them, fold review feedback back into these skills so the same comment is never needed twice, and treat them as products with owners and versions. Shared AI infrastructure: build on BILL's shared AI platform and tooling instead of one-off solutions, and contribute skills, tool integrations and improvements back so every team benefits. We’d love to chat if you have: 8+ years of professional backend engineering experience building and operating distributed systems in production. Strong Java (or another JVM language) and relational database skills, with experience designing services around clear domain boundaries. Deep API design experience in both GraphQL and REST: schema and resource modeling, pagination and filtering, idempotency, error design, versioning and backward compatibility. Federated GraphQL experience (entity ownership, schema checks, moving fields between subgraphs) is a strong plus. A track record of leading a rebuild or migration of a production system off a monolith or legacy platform, end to end. Hands-on, daily use of AI coding agents (for example Claude Code or Cursor) to ship production code, with good judgment about when agent output can be trusted and how to verify it. Examples of using AI beyond code generation, in design, review, testing, release or production operations, with measurable impact on delivery or quality. Experience building reusable agent assets (skills, context files, custom agents, tool integrations) that other engineers adopted, ideally on a shared internal AI platform you contributed back to. A record of production impact at scale: software that serves a large user base or moves significant money and has run reliably over time. We care more about what you shipped and how it held up than about the list of tools you used. Experience with event-driven architecture and with choosing between synchronous and asynchronous integration. Experience building in a correctness-critical domain where data integrity, idempotency and auditability are requirements. Experience running services on AWS with strong testing, observability and incident practices. For Senior Staff (P5): experience setting backend technical direction across several teams and landing it. Nice to have: experience in payments, accounts payable or receivable, or accounting systems, and experience exposing APIs as tools for AI agents (for example through MCP).
