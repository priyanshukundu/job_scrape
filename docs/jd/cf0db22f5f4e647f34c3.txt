Staff Software Engineer, Edge AI Delivery Role Overview: The Edge AI team works across software, hardware, sensors, and machine learning to lead the way in Physical AI on Analog Devices platforms. We are seeking a Staff Software Engineer to own the path from development to delivery, shaping how we design, test, and release the models, tools, and SDKs our customers build on. This role sets the engineering standards that turn research-grade code into production software customers can rely on, and drives their adoption across a team of AI, DSP, and embedded engineers. Key Responsibilities: Own release readiness for customer deliverables. Define and run the release process for models, tools, and software, including versioning, packaging, branching strategy, release criteria, and change management, so that every release meets agreed quality standards and is reproducible and traceable, with clear release notes and license tracking. Guide how we build production software for external customers, bringing expertise in software architecture, design patterns, API and library design, and documentation practices. Help the team turn research code into maintainable, well-documented software that is easy for customers to adopt, integrate, and support. Design and maintain CI/CD pipelines that automatically build, test, and package software and model artifacts across multiple platforms and toolchains, including cross-compiled embedded targets. Raise the bar for software quality across the team. Establish automated testing (unit, integration, regression, and on-target) and coach engineers of varied experience to adopt it. Document processes clearly so the team can follow them independently, and continuously improve them based on how they work in practice. Collaborate with AI, embedded, and hardware teams to align release plans with model development, SDK roadmaps, and silicon availability. Qualifications: Bachelor’s degree in computer science, computer engineering, or a related field, or equivalent experience. 8+ years of industry experience in software engineering, including significant experience delivering production software to external customers. Strong Python and C++ skills, with sound judgment in software architecture, design patterns, and API and library design. Demonstrated ownership of software release processes, including release gating, semantic versioning, packaging, artifact management, and reproducible builds. Deep hands-on experience designing and maintaining CI/CD pipelines (GitHub Actions, Jenkins, or similar). Experience establishing test automation strategy and quality practices across a development team. Experience with build systems such as CMake, Bazel, or similar, including cross-platform or cross-compiled builds. Proficiency with containerization (Docker), Bash, and Git workflows. Experience writing and maintaining documentation for external users, such as API references, integration guides, and release notes. A track record of driving process adoption without reporting-line authority, by working with developers rather than imposing process on them. Preferred Skills: These are helpful but not required. We don’t expect expertise in every area. Working knowledge of machine learning workflows, enough to understand how models are trained, evaluated, and handed off for deployment. MLOps experience, including model registries, model artifact versioning, and automated model validation in CI. Working knowledge of data engineering, such as data pipelines, dataset versioning, and tools like DVC, MLflow, or similar. Experience building, testing, or releasing software for embedded targets or RTOS environments such as Zephyr, including tooling like west and on-target test automation. Experience with hardware-in-the-loop test setups or device lab automation. Familiarity with software supply chain practices such as SBOMs, license compliance, vulnerability scanning, and signed artifacts. Familiarity with infrastructure-as-code (Terraform, Ansible) and cloud or on-prem compute management. Knowledge of Analog Devices hardware platforms or similar embedded ecosystems.
